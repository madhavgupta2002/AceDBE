## Short Notes Format Guide (Subjective Exam - Design Your Thinking)

### Exam Context
- **Exam Pattern:** 4 Subjective Questions, 25 Marks Each (100 Marks Total, 60 Mins)
- **Format:** Digital typing, ~200 words per question (structured framework breakdown, points, and real-world benchmark examples)

---

### 1. Document Structure

```
## MODULE {n}: {Module Title}

---

### {Topic Name}

{Content Block: Tables / Formulas / Bullets}

{Question Block: Subjective 25M Blueprint / CLA MCQs}

---

### {Next Topic}
...

---

## Quick Reference: {Summary Title}
## Key Decision Rules Summary
```

---

### 2. Content Block Patterns

**Pattern A — Concept Table** (most common; for definitions, classifications, comparisons):

```markdown
| Column1 | Column2 | Column3 |
|---------|---------|---------|
| **Bold Term** | Description | Key detail / Example |
```

**Pattern B — Formula / Equation Block**:

```markdown
$$\text{Creativity} = \text{Novelty} + \text{Utility}$$
$$\text{Innovation} = \text{Creativity} \times \text{Scale}$$
```

**Pattern C — Bullet Points** (for single-line facts, mnemonics, rules):

```markdown
- **Bold Key Term:** One-line explanation
- **Bold Key Term:** One-line explanation
```

---

### 3. Question Block Formats

**Format A — Subjective Question (25-Mark Model Answer)**:

Tag with `**PYQ (Subjective):**`, `**CLA (Subjective):**`, or `**Q (Subjective):**`. The complete structured answer sits inside the `>` blockquote (~200 words, points-based, with real-world application):

```markdown
> **PYQ (Subjective):** Design the stakeholder map of poor voter turnout problem. Identify pains and gains.
> - **Core Anchor:** Poor voter turnout is a systemic multi-stakeholder issue requiring pain reduction and gain amplification.
> - **Stakeholder Analysis:**
>   - **Individual Voters:** *Pains:* Apathy, long queues, cynicism. *Gains:* Civic empowerment, voice in governance.
>   - **Political Candidates:** *Pains:* Distrust, weak outreach. *Gains:* Legitimate mandate, visibility.
>   - **Employers / Workplaces:** *Pains:* Lost productivity. *Gains:* Brand goodwill, legal compliance.
>   - **Election Commission:** *Pains:* Logistical friction, voter registration bugs. *Gains:* Higher turnout, institutional credibility.
> - **Conclusion:** Sustainable turnout requires aligning incentives across all stakeholders ✓
```

**Format B — Conceptual / MCQ Validation** (from CLAs):

Tag with `**CLA:**` or `**PYQ:**`. Question stem followed by bold answer with `✓`:

```markdown
> **CLA:** What are the two necessary qualifiers of a creative idea?
> - **Novelty + Utility** ✓
>
> **CLA:** High intelligence automatically guarantees high creativity.
> - **False** (Creativity is mediated by Low Latent Inhibition and divergent thinking) ✓
```

---

### 4. Formatting Conventions

| Element | Convention |
|---------|-----------|
| **Key terms** | Always **bold** on first/primary mention |
| **Answers / Conclusions** | **Bold** + `✓` checkmark |
| **Question Source Tag** | Use `**PYQ (Subjective):**`, `**Q (Subjective):**`, `**CLA:**`, or `**PYQ:**` |
| **Negations** | Use **NOT** in bold caps: `**NOT**` |
| **Formulas** | Inline `$...$` for within text; `$$...$$` for standalone |
| **Tips / Edge cases** | `*(Italicized in parentheses)*` |
| **Section dividers** | `---` between topics |
| **Checkmarks** | Every answer/conclusion ends with `✓` — no exceptions |

---

### 5. End-of-Document Summaries

**Quick Reference Table** — condenses frameworks, methods, and benchmark examples:

```markdown
## Quick Reference: Frameworks & Benchmark Applications

| Framework | Core Question / Rule | Benchmark Real-World Example |
|-----------|----------------------|------------------------------|
| **SCAMPER** | 7 triggers for product evolution | Adaptive Eyewear / Helmets / Pencil |
| **Analogous Design** | Cross-domain solution borrowing | Airplane food service for Cafeteria |
| **5 Whys** | Drill down to root causes | Machine pump intake filter failure |
```

**Key Decision Rules Summary** — one-liner rules for exam recall:

```markdown
## Key Decision Rules Summary

| Rule | Detail |
|------|--------|
| **Rule Name** | One-line rule |
```

---

### 6. Content Density Rules

| Principle | Detail |
|-----------|--------|
| **Everything but in revision form** | Full syllabus coverage, zero filler prose — every line is either a fact, formula, table row, or subjective point |
| **Tables over paragraphs** | If 3+ related items exist, use a table |
| **One concept → its questions** | Attach the 25M subjective blueprint and CLA questions directly under the matching concept |
| **Bold = examinable** | If it's bold, it's been tested or is a key scoring keyword |
| **No redundant explanation** | If the table says it, don't repeat it in bullets below |

---

### 7. Input → Output Workflow

**Inputs required:**
1. Course lecture notes (full syllabus)
2. All classroom MCQs (CLAs, quizzes)
3. Reference subjective questions (past exams)

**Transformation rules:**
1. Compress each concept into the smallest correct representation (table/formula/bullets).
2. Attach subjective 25M blueprints (`**Q (Subjective):**`) and CLA conceptual questions directly below the relevant concept.
3. Include concrete real-world benchmark examples for all frameworks.
4. Add Quick Reference and Key Decision Rules summaries at the end.
